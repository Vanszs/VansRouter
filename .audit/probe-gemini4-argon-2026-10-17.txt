E) Sampling params on Argon (deciding the direct claim in eb373017:
   "Generation config — Gemini 4 removed the sampling params, forwarding them
   fails the request").
   Payload validation runs BEFORE the quota check on this API — proven by
   generationConfig.totallyUnknownField => 400 "Unknown name ... Cannot find
   field" and generationConfig.thinkingBudget => 400 "Unknown name
   thinkingBudget", both returned instead of 429.

   Against that control:
     gemini-4-argon  generationConfig.temperature = 0.7  => 429 (quota)
     gemini-4-argon  generationConfig.temperature = 999  => 400
        "...temperature: temperature must be <= 2"  <- a VALUE error
     gemini-4-argon  generationConfig.topK = 999        => 429 (quota)
     gemini-3.8-flash generationConfig.topK = 999       => 200
   temperature/topP/topK are KNOWN fields on gemini-4-argon: had they been
   removed we would have seen the "Unknown name" 400 the thinkingBudget control
   produces. => the "Gemini 4 removed the sampling params" premise does NOT
   reproduce, so the sampling-param drop in eb373017 is NOT adopted.
   (The functionResponse-last reordering in the same commit is a separate,
   scoped, gemini-4-only change that could not be probed for lack of quota;
   it is adopted on its own merits and cannot affect Gemini 3 models.)
